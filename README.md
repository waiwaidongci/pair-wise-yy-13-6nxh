# hxyfront-62012 纺织染整小样管理

源提示词编号：7

纺织染整实验室小样管理前端系统：记录面料成分、克重、染料配方、浴比、温度曲线、保温时间、后整理方式、色差值与客户评审结果；支持小样批次列表、配方比例展示、Lab 色差对比、工艺曲线摘要和按客户订单筛选。

本次新增**离线续办**能力：断网可继续登记批次、记录复测色差；网络恢复后按配方版本逐项合并，差异列清裁决，评审结果受保护。

## 技术栈

React 19 + Vite + TypeScript（无后端，用 localStorage 模拟服务端数据源，可注入故障）

## 本地运行

```bash
npm install
npm run dev
```

开发端口：62012

## 离线续办处理规则

1. **断网暂存**：登记批次（含配方版本、面料、克重、染料配方、浴比、温度曲线、标准 Lab 等）与送样复测（实测 Lab、ΔE）先入离线队列并本地立即可见。
2. **按版本对账**：网络恢复后先拉取"别处"更新。远端配方版本与离线基准不同，基于旧版本的复测与客户评审**立即失效**，需重新复测/重新评审；历史结论不删除，保留在批次处理过程中。
3. **逐项三方合并**：以离线开始时的批次快照为基准——
   - 仅本地改过 → 取离线值；仅服务端改过 → 保留别处更新；
   - 两边都改成不同值 → 列为冲突，界面逐项呈现"离线所记 / 服务端现值"，人工裁决后才写入，不自动覆盖；
   - 复测色差按 L\*/a\*/b\* 分量逐项裁决，ΔE 对照标准样重算。
4. **评审保护**：服务端已确认（valid）的客户评审，在任何字段合并中都不会被盖掉；评审仅允许在线提交。
5. **失效重认**：配方版本变更后，失效复测可直接基于新版本重新复测确认；评审需客户在线重新确认。
6. **失败保留重试**：上送/合并失败的待办原样保留在队列（记录原因与尝试次数），其余待办继续处理，随时可重试；可勾选"注入一次故障"演示该流程。
7. **全程留痕**：离线暂存、别处修订、差异冲突、评审保护、版本失效、合并成功/失败等处理过程全部写入批次日志（在批次卡片查看）。

### 演示路径

- 切换"模拟断网" → 登记新批次或对已有批次记录复测 → 队列出现待办；
- 恢复网络即自动合并；也可在离线时先用批次卡片"模拟'别处'修订配方"再联网，观察版本失效与差异裁决；
- 勾选"注入一次故障"后合并，观察失败保留与重试。

## 验证

```bash
npm run verify          # 类型检查 + 引擎单测 + 合并流水线集成测试 + React 挂载冒烟
npm run verify:engine   # 纯函数合并规则（28 项）
npm run verify:pipeline # 离线→冲突→失败重试→版本失效完整流水线（34 项）
npm run verify:smoke    # jsdom 真实挂载与关键交互
```

核心代码：

- `src/types.ts`：批次、配方版本、复测、评审、离线待办与冲突模型
- `src/lib/engine.ts`：ΔE、三方差异检测、逐项合并、版本失效等纯函数
- `src/lib/sync.ts`：网络恢复后的合并流水线
- `src/lib/server.ts`：localStorage 模拟服务端（别处修订、客户评审、故障注入）
- `src/lib/useLab.ts`：React 状态、离线队列与自动同步
- `src/components/`：状态栏、登记/复测表单、离线裁决队列、批次与处理日志
